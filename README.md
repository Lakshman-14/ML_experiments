# Visit with Us: Tourism Package Purchase Prediction

An end-to-end MLOps project for estimating general tourism-package purchase
propensity using customer and sales interaction data. The supplied `ProdTaken`
label is not specific to the Wellness Tourism Package; the model must not be
interpreted as a Wellness-specific predictor.

## Repository layout

```text
.
├── .github/workflows/pipeline.yml
├── app.py
├── data/tourism.csv
├── model/                 # Trained model and metrics generated by training
├── notebooks/             # Executed notebook and HTML submission
├── src/
│   ├── prepare_data.py
│   ├── train_model.py
│   └── validate_data.py
└── tests/test_pipeline.py
```

## Run locally

Use Python 3.10 or newer.

```bash
python -m pip install -r requirements-notebook.txt
python -m src.validate_data
python -m src.prepare_data
python -m src.train_model
python -m unittest discover -s tests -v
streamlit run app.py
```

The split files are created under `artifacts/splits/`; the fitted preprocessing
and estimator pipeline is saved as `model/best_model.joblib`. Cross-validation
results and held-out test metrics are saved alongside the model.

## GitHub Actions

`.github/workflows/pipeline.yml` validates the data, creates train/test splits,
passes them to the model-training job as an Actions artifact, tests the pipeline,
and commits changed model outputs to the repository's current default branch
(`master`). The workflow needs Actions to be
enabled and repository workflow permissions to allow `GITHUB_TOKEN` to write
contents. The generated model commit is excluded from the next workflow run via
`paths-ignore: model/**`, preventing retraining loops.
